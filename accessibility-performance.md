# accessibility-performance.md — Доступність і продуктивність

> Knowledge-файл для Devin AI. Обов'язкові вимоги, узгоджені з темною темою `design.md` і анімаціями з `animations.md`.

## Контраст (WCAG AA, темна тема)

- `--text-primary` (`#F5F5F7`) на `--bg-base` (`#0A0A0F`) — контраст ~18:1, ОК для будь-якого тексту.
- `--text-muted` (`#9A9AA8`) на `--bg-base` — перевірити, що контраст не нижче 4.5:1 для основного тексту; використовувати `text-muted` тільки для допоміжних підписів, не для важливого контенту форми чи CTA.
- `--accent-live` (`#F5306B`) і `--accent-gold` (`#E8B34F`) як фон кнопки з білим текстом — перевірити контраст тексту на кнопці (мінімум 4.5:1 для звичайного розміру шрифту, 3:1 для великого/жирного). Якщо не проходить — текст кнопки залишити `--bg-base` (темний) замість білого на світлих акцентних кольорах.
- Ніколи не покладатись лише на колір для передачі стану (помилка форми — завжди колір + іконка + текст, не тільки червона рамка).

## Фокус-стани

- Візуальний фокус **обов'язковий** на всіх інтерактивних елементах (посилання, кнопки, інпути): `focus-visible:ring-2 focus-visible:ring-accent-tech focus-visible:ring-offset-2 focus-visible:ring-offset-bg-base`. Ніколи `outline: none` без заміни.
- Порядок табуляції — логічний, відповідає візуальному порядку секцій.
- Мобільне меню (Alpine `x-data`) — фокус переходить у меню при відкритті, повертається на тригер при закритті (focus trap).

## prefers-reduced-motion

Обов'язкова перевірка в CSS і JS для всіх анімацій з `animations.md`:

```css
@media (prefers-reduced-motion: reduce) {
  * {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

```js
const prefersReducedMotion = window.matchMedia('(prefers-reduced-motion: reduce)').matches;
if (prefersReducedMotion) {
  // не запускати canvas-анімацію сфери, показати статичний SVG/PNG кадр
  // не запускати growth-тікер інкремент — одразу показати кінцеве значення
}
```

## Семантика і screen readers

- Використовувати семантичні теги: `<header>`, `<nav>`, `<main>`, `<section>`, `<footer>`, а не суцільні `<div>`.
- Кожен `<nav>` — з `aria-label` ("Головна навігація").
- Іконки без тексту (соцмережі, hamburger-меню) — з `aria-label` або `sr-only`-текстом.
- Форма: кожен `<input>` пов'язаний з `<label>` (навіть якщо label візуально приховано через `sr-only`, а не `placeholder` замість label).
- Honeypot-поле — обов'язково з `aria-hidden="true"` і `tabindex="-1"`, щоб скрінрідери його не озвучували.
- Live-регіони: growth-тікер і статус відправки форми — `aria-live="polite"`, щоб зміни озвучувались без переривання користувача.

## Core Web Vitals

- **LCP** (< 2.5с): hero-заголовок і перший видимий текст — не блокувати рендер шрифтами; `font-display: swap` на всіх кастомних шрифтах; canvas-анімація сфери ініціалізується **після** першого фарбування (paint), не блокує LCP.
- **CLS** (~0): всі `<img>` з явними `width`/`height` або `aspect-ratio`; canvas-контейнер hero має зафіксовану висоту через CSS до завантаження JS; шрифти через `font-display: swap` з fallback, що має близькі метрики (уникнути "стрибка" тексту).
- **INP**: мінімум блокуючого JS у головному потоці; важкі обчислення (частинки сфери) — рахувати ефективно, throttlити до 30-60fps залежно від пристрою (перевірка `navigator.hardwareConcurrency` або простий FPS-монітор для авто-даунгрейду складності на слабких пристроях).

## Продуктивність зображень

- Формати: WebP/AVIF з fallback на JPEG через `<picture>`.
- Аватарки кейсів і команди — стиснуті, не більше 100-150KB кожна.
- OG-зображення — окремий оптимізований файл, не використовується як основне зображення на сторінці.
- `loading="lazy"` + `decoding="async"` на всіх зображеннях нижче першого екрана.

## Бюджет продуктивності

- Загальна вага сторінки (без шрифтів із Google Fonts CDN, **без урахування GSAP+Lenis ~150KB**, які додані свідомо під топ-рівень анімацій) — не більше ~500KB власного коду/зображень.
- Lighthouse Performance — ціль 85+ на мобільному (нижче за попередню ціль 90+ через важчий анімаційний стек — свідомий компроміс), 95+ на десктопі.
- Одна WebGL-рендер-петля + один pinned ScrollTrigger активні одночасно (див. `animations.md` v2), пауза поза viewport і при неактивній вкладці (`document.hidden`) — обов'язково і для Lenis, і для WebGL rAF-лупу, інакше батарея мобільних пристроїв сідає навіть при неактивній вкладці.
- `prefers-reduced-motion` при важчому стеку — не опція, а обов'язковий повний вимикач Lenis/ScrollTrigger-руху/WebGL (див. `animations.md` v2, розділ "Правило №1").
