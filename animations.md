# animations.md — Специфікація анімацій

> Knowledge-файл для Devin AI. Описує конкретні анімації на основі відео-референсів. Ціль: рух, що відчувається як продукт, а не як декор. Один оркестрований момент craще за розкидані ефекти.

## Правило №1: prefers-reduced-motion

Кожна анімація нижче **обов'язково** обгортається перевіркою `prefers-reduced-motion: reduce` — у цьому випадку показувати статичний кінцевий стан без руху. Це не опціонально.

## 1. Hero: анімована частинкова сфера/орбіта

Референс: обертова сфера з частинок (nodes + з'єднувальні лінії), що пульсує градієнтом `accent-live → accent-tech`, з тонкими "даними" збоку (mono-текст, що імітує технічні лог-рядки).

Реалізація:
- Canvas 2D (не Three.js — зайва вага для одного статичного лендінгу) з частинками, розташованими по сфері (обчислення через параметричні координати), що повільно обертається (`requestAnimationFrame`, ~0.05 рад/сек).
- Лінії між найближчими частинками рендеряться з opacity, що залежить від відстані.
- Колір частинок: градієнт від `--accent-live` до `--accent-tech` залежно від позиції на сфері.
- Обов'язково: **пауза анімації, коли canvas поза viewport** (через `IntersectionObserver`) і коли вкладка неактивна (`document.hidden`) — критично для продуктивності.
- Мобільна версія: спростити до статичної SVG-сфери з CSS `@keyframes rotate` (значно дешевше для слабких пристроїв), або взагалі прибрати на екранах < 480px.

## 2. Скрол-reveal секцій (mosaic/pixel transition)

Референс: перехід між секціями через мозаїчну піксельну сітку (чорно-білі квадрати), що "розсипається"/збирається, відкриваючи наступний контент.

Реалізація для лендінгу (спрощена, без важкого canvas-effect на кожну секцію — використати вибірково, 1-2 рази максимум, інакше набридає):
- Застосувати **тільки** на переході з hero в секцію "Як це працює" — як єдиний "вау"-момент сторінки, а не скрізь.
- CSS-based: сітка з `div`-квадратів (10×6), кожен з `transition-delay`, що по черзі зникають (`opacity` + `scale`) при вході секції у viewport через `IntersectionObserver`, відкриваючи контент під ними.
- Інші секції — простий, стриманий reveal: `opacity: 0 → 1` + `translateY(24px) → 0`, тривалість 500-600ms, easing `cubic-bezier(0.16, 1, 0.3, 1)`, стагерований delay 80-100ms між дочірніми елементами картки/списку.

## 3. Growth-тікер (сигнатурний елемент)

- Лічильник доходу/стрімерів інкрементується від 0 до цільового значення при вході у viewport (не безкінечно — один раз, потім статичний, з можливістю періодичного м'якого "пульсу" підсвітки раз на ~8 секунд, щоб показати "живість" без нав'язливості).
- Реалізація: JS `requestAnimationFrame` з easing `easeOutExpo`, форматування чисел через `Intl.NumberFormat`.
- Візуально — панель у стилі терміналу (border-subtle, mono-font, невеликий "статус"-індикатор — пульсуюча крапка `accent-tech`, що імітує "live"-стан).

## 4. Marquee-стрічка (опційно, під шапкою або над footer)

Референс: рухома стрічка новин зверху сторінки. Використати для соціального доказу: нескінченна горизонтальна стрічка з ніками/аватарками стрімерів або короткими фразами ("640+ стрімерів у команді · Дохід від $2000/міс · Без досвіду").

Реалізація: CSS `@keyframes marquee` з `translateX(-50%)` на контейнері, що містить контент, продубльований двічі (для безшовного циклу), `animation-play-state: paused` на hover.

## 5. Hover-мікровзаємодії

- Картки кейсів: підйом `translateY(-4px)` + м'яке зовнішнє світіння (`box-shadow` з `accent-live`, opacity 0.15) за 200ms.
- Кнопки CTA: заливка кольором проявляється зліва направо (`background-position` transition) або легке масштабування `scale(1.02)`.
- Навігація: підкреслення, що виїжджає зліва направо при hover (`transform: scaleX(0 → 1)`, `transform-origin: left`).

## 6. Форма заявки

- При фокусі на полі — border переходить у `accent-tech`, легкий glow.
- При успішній відправці — форма плавно (300ms fade+scale) заміняється на success-повідомлення з іконкою-чекмарком, що промальовується (`stroke-dashoffset` анімація SVG).
- При помилці — легкий horizontal shake (`translateX` -6px/+6px, 2 цикли, 300ms) на полі з помилкою.

## Продуктивність — обмеження

- Не більше **однієї** canvas-анімації одночасно активної на екрані.
- Всі scroll-based анімації — через `IntersectionObserver`, ніколи через `scroll`-event listener напряму (уникати layout thrashing).
- `will-change` використовувати точково, тільки на елементах, що активно анімуються, і прибирати після завершення.
- Загальний бюджет: сторінка має залишатись плавною (60fps) на середньому мобільному пристрої — тестувати через Chrome DevTools Performance при throttling "Mid-tier mobile".
